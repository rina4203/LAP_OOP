# Фургон кави

Консольний застосунок на Java, який завантажує фургон певного об'єму кавою на
певну суму, сортує вантаж за співвідношенням ціни та ваги й шукає товари
із заданим діапазоном параметрів якості.

Два режими роботи:

- **звіт** (`CoffeeVanApplication`) — читає дані з файлів, сам завантажує
  фургон і виводить результати;
- **інтерактивний** (`CoffeeVanShell`) — усе те саме вручну: додавання,
  пошук, зміна й видалення товарів у каталозі та фургоні.

## Завдання

Завантажити фургон певного об'єму вантажем на певну суму з різних сортів кави,
які знаходяться в різних фізичних станах (зерно, мелене, розчинне в банках
і пакетиках). Урахувати об'єм кави разом з упаковкою. Провести сортування
товарів на основі співвідношення ціни та ваги. Знайти товар у фургоні, що
відповідає заданому діапазону параметрів якості.

## Як це працює

1. Параметри фургона (об'єм, бюджет) і діапазон якості для пошуку зчитуються
   з [`van.properties`](src/main/resources/van.properties).
2. Каталог товарів зчитується з
   [`coffee-catalog.csv`](src/main/resources/coffee-catalog.csv).
3. `VanLoader` завантажує товари в порядку каталогу; товар, що не вміщується
   за об'ємом (з урахуванням упаковки) чи бюджетом, пропускається.
4. Вантаж сортується за ціною кілограма кави (від найдешевшої).
5. У фургоні шукаються товари, у яких аромат, кислотність і тіло
   потрапляють у задані межі.

Об'єм товару рахується так:
`вага / насипна густина стану кави × коефіцієнт упаковки`.
Густина залежить від фізичного стану: для зерен — від обсмаження, для меленої
кави — від помелу, для розчинної — від технології виробництва.

## Структура

```
ua.lab.coffeevan
├── CoffeeVanApplication      точка входу режиму звіту
├── model                     предметна область
│   ├── Coffee                абстрактний кавовий товар
│   │   ├── CoffeeBeans       кава у зернах (RoastLevel)
│   │   ├── GroundCoffee      мелена кава (GrindSize)
│   │   └── InstantCoffee     розчинна кава в банках і пакетиках (InstantProcess)
│   ├── CoffeeVariety         сорт: арабіка, робуста, ліберика, ексцельза
│   ├── PackagingType         упаковка та її коефіцієнт об'єму
│   ├── DisplayNamed          спільний інтерфейс переліків (код + назва)
│   ├── Quality               параметри якості (аромат, кислотність, тіло)
│   └── QualityRange          діапазон параметрів якості
├── stock
│   ├── CoffeeCollection      абстрактний список товарів: додавання, заміна,
│   │                         видалення, пошук, сортування
│   └── CoffeeCatalog         каталог - товари, доступні для завантаження
├── van
│   ├── CoffeeVan             фургон (CoffeeCollection з обмеженням об'єму
│   │                         й бюджету)
│   ├── VanLoader             заповнення фургона товарами з каталогу
│   └── VanWorkspace          каталог + фургон: переміщення товарів між ними
├── config
│   ├── VanConfig             параметри ініціалізації
│   └── VanConfigReader       читання параметрів з .properties
├── io
│   ├── CoffeeCatalogReader   читання каталогу з CSV
│   ├── CoffeeCatalogWriter   запис каталогу в CSV
│   ├── CoffeeLineFormat      рядок каталогу <-> товар, зміна поля товару
│   ├── CoffeeForm            фізичний стан у файлі: BEANS, GROUND, INSTANT
│   ├── ValueParser           розбір чисел і кодів зі зрозумілими помилками
│   └── DataSources           відкриття файлів і вбудованих ресурсів (UTF-8)
├── report
│   └── CargoReportPrinter    виведення таблиць у консоль
├── console
│   ├── CoffeeVanShell        точка входу інтерактивного режиму
│   └── command               команди: Command (інтерфейс), AbstractCommand,
│                             Arguments, AddCommand, EditCommand, ...
└── exception
    ├── CargoLoadingException товар не вміщується у фургон
    └── InvalidDataException  некоректні дані у файлах
```

**ООП у проєкті:**

- **Успадкування** — `CoffeeBeans`, `GroundCoffee`, `InstantCoffee` розширюють
  абстрактний `Coffee`: це різні фізичні стани одного товару.
- **Поліморфізм** — `getBulkDensity()`, `getPhysicalState()`,
  `getStateDetails()` перевизначаються в підкласах; `CoffeeVan` працює з будь-якою
  кавою через тип `Coffee`.
- **Інкапсуляція** — усі поля `private final`, значення перевіряються
  в конструкторах, вантаж фургона доступний лише для читання.
- **Композиція** — упаковка й якість є окремими типами, а не підкласами.
- **Шаблонний метод** — `CoffeeCollection.add()` та `replace()` викликають
  `checkCanAdd()`; каталог приймає будь-який товар, а `CoffeeVan`
  перевизначає перевірку, додаючи обмеження об'єму й бюджету.
- **Патерн «Команда»** — кожна команда інтерактивного режиму є окремим
  класом з інтерфейсом `Command`; оболонка викликає `execute()`, не знаючи,
  що саме робить команда. Уся логіка — у `VanWorkspace` і моделі, консольний
  код лише розбирає введений текст (вимога мінімальної роботи з консоллю).

## Запуск

### IntelliJ IDEA

1. Відкрити теку `LAB_OOP`. Якщо IDEA запропонує *Load Maven Project* —
   погодитися (або ПКМ по `pom.xml` → *Add as Maven Project*).
2. Вказати JDK 17 або новішу: *File → Project Structure → Project → SDK*.
3. Запустити `CoffeeVanApplication` (зелена стрілка біля методу `main`).
4. Тести: ПКМ по `LAB1/src/test/java` → *Run 'All Tests'*
   (або *Run with Coverage*).

### З консолі (Windows)

Скрипт [`run.cmd`](run.cmd) сам збирає програму (якщо її ще не зібрано або
змінився код), вмикає UTF-8 у консолі та запускає програму:

```bash
LAB1\run.cmd
```

| Команда                  | Що робить                                  |
|--------------------------|--------------------------------------------|
| `run`                    | стандартні дані з `src/main/resources`     |
| `run list`               | перелік готових сценаріїв                  |
| `run <назва>`            | дані з теки `scenarios/<назва>`            |

Файли зі стандартними даними читаються напряму, тому після їх зміни
програму не треба перезбирати — достатньо запустити `run` ще раз.

### Інтерактивний режим

```bash
LAB1\run.cmd shell
```

або з даними сценарію: `LAB1\run.cmd shell wholesale`. В IDEA —
зелена стрілка біля `main` у [`CoffeeVanShell`](src/main/java/ua/lab/coffeevan/console/CoffeeVanShell.java).

Є два списки: **каталог** (`catalog`) — товари, доступні для завантаження,
і **фургон** (`van`) — завантажені товари. Номери товарів — як у таблицях,
з 1.

| Команда                                      | Що робить                                        |
|----------------------------------------------|--------------------------------------------------|
| `help`                                       | перелік команд                                   |
| `list [catalog\|van]`                        | показати каталог і/або фургон                    |
| `add [рядок каталогу]`                       | додати товар у каталог (без рядка — покроково)   |
| `edit <catalog\|van> <№> <поле> <значення>`  | змінити поле товару                              |
| `remove <catalog\|van> <№\|all>`             | видалити товар (або всі)                         |
| `find <частина назви>`                       | знайти товари за назвою в обох списках           |
| `van [<об'єм_л> <бюджет_грн>]`               | показати фургон або змінити його об'єм і бюджет  |
| `load [<№>\|all]`                            | перенести товар з каталогу у фургон (або все)    |
| `unload <№\|all>`                            | повернути товар з фургона в каталог              |
| `sort [catalog\|van] [asc\|desc]`            | сортування за ціною кілограма                    |
| `search [catalog\|van] [<аромат> <кисл.> <тіло>]` | пошук за діапазоном якості, напр. `search 7-10 5-9 5-8` |
| `save <catalog\|van> <файл>`                 | зберегти список у CSV                            |
| `exit`                                       | вийти                                            |

Поля для `edit`: `state`, `name`, `variety`, `weight`, `price`, `packaging`,
`aroma`, `acidity`, `body`, `feature` (або українською: `назва`, `ціна`,
`аромат`...). Коди значень можна вводити малими літерами, дробові числа —
з комою.

Приклад сеансу — завантажити фургон вручну, відсортувати й знайти товар:

```
> van 20 6000
> add beans;Моя арабіка;arabica;1000;900;paper_bag;8;6;7;medium
> load 16
> load
> sort
> search 7-10 5-9 5-8
> edit van 1 price 600
> unload 2
> remove catalog all
> save van my-van.csv
> exit
```

### Готові сценарії

У теці [`scenarios`](scenarios) лежать набори даних, у кожному з яких змінено
щось одне. Якщо в сценарії немає `van.properties` чи `coffee-catalog.csv`,
береться стандартний файл. Опис кожного сценарію — у його `about.txt`.

| Сценарій               | Що показує                                                  |
|------------------------|-------------------------------------------------------------|
| `big-van`              | великий фургон — обмежує вже бюджет, а не місце             |
| `rich-budget`          | необмежений бюджет — обмежує лише об'єм                     |
| `tiny-van`             | маленький фургон — вміщуються лише дрібні пакунки           |
| `small-first`          | той самий товар в іншому порядку — завантажується більше    |
| `aroma-lovers`         | пошук найароматнішої кави                                   |
| `strong-coffee`        | пошук міцної кави                                           |
| `nothing-found`        | пошук, під який нічого не підходить                         |
| `instant-only`         | лише розчинна кава: банка проти пакетиків                   |
| `wholesale`            | великий каталог (30 товарів) і великий фургон               |
| `error-packaging`      | помилка: зерно у скляній банці                              |
| `error-typo`           | помилка: одрук у назві упаковки                             |
| `error-quality`        | помилка: оцінка якості поза шкалою                          |
| `error-fields`         | помилка: у рядку каталогу бракує полів                      |
| `error-missing-budget` | помилка: не вказано бюджет                                  |
| `error-range`          | помилка: мінімум діапазону більший за максимум              |

Тест `ScenariosTest` перевіряє, що звичайні сценарії завантажують фургон,
а сценарії `error-*` завершуються зрозумілою помилкою.

### Maven

У IDEA: вкладка *Maven* → *LAB_OOP* → *Lifecycle* → `verify`.

З терміналу (з кореня `LAB_OOP`) — через Maven Wrapper, встановлювати Maven
не потрібно, достатньо JDK 17+ і змінної `JAVA_HOME`:

```bash
./mvnw verify
```

```bash
java -jar LAB1/target/coffee-van-1.0.jar
```

Можна передати власні файли: `java -jar coffee-van-1.0.jar van.properties catalog.csv`.

Звіт про покриття тестами — `LAB1/target/site/jacoco/index.html`.
Збірка завершується помилкою, якщо тести покривають менше 95% рядків.

## Формат файлів

`van.properties`:

```properties
van.capacity.liters=18
van.budget=5600
search.aroma.min=7
search.aroma.max=10
search.acidity.min=5
search.acidity.max=9
search.body.min=5
search.body.max=8
```

`coffee-catalog.csv` — один товар у рядку, поля через `;`:

```
стан;назва;сорт;вага_г;ціна_грн;упаковка;аромат;кислотність;тіло;особливість
BEANS;Colombia Supremo;ARABICA;1000;1150.00;VACUUM_PACK;8;6;7;MEDIUM
GROUND;Espresso Italiano;ARABICA;250;330.00;TIN_CAN;8;5;8;FINE
INSTANT;Crema Sticks;ARABICA;50;95.00;SACHET;5;3;4;AGGLOMERATED
```

| Стан      | Упаковки                                | Особливість                                 |
|-----------|-----------------------------------------|---------------------------------------------|
| `BEANS`   | `PAPER_BAG`, `VACUUM_PACK`              | `LIGHT`, `MEDIUM`, `DARK`                   |
| `GROUND`  | `PAPER_BAG`, `VACUUM_PACK`, `TIN_CAN`   | `FINE`, `MEDIUM`, `COARSE`                  |
| `INSTANT` | `GLASS_JAR`, `TIN_CAN`, `SACHET`        | `FREEZE_DRIED`, `AGGLOMERATED`, `SPRAY_DRIED` |

## Технології

Java 17, Maven, JUnit 5, Mockito, JaCoCo.
